# ESP32 Network для Windows

Готовое приложение: `ESP32-Network.exe` рядом с папкой проекта.
Установка Python для его запуска не нужна. Приложение предназначено для Windows x64.

## Работа через окно

1. Подключите ESP32 кабелем USB с передачей данных.
2. Закройте Serial Monitor в VS Code, Arduino IDE и других программах.
3. Запустите exe, выберите COM-порт и нажмите **Подключить USB**.
   Приложение перезапустит плату и получит список Wi-Fi сетей.
4. Выберите сеть в таблице, введите пароль и нажмите **Подключиться к Wi-Fi**.
   Для открытой сети пароль не нужен.
5. Дождитесь сканирования локальной сети. Выберите устройство, при желании
   задайте своё имя и нажмите **Выбрать и сохранить**.
6. После сохранения начнутся фоновый поиск устройства по MAC и диагностика.
   IP устройства, состояние Wi-Fi и ICMP-проверка yandex.ru отображаются в окне.

**Начать заново** перезапускает ESP32 и возвращает к выбору сети.
При каждом запуске платы устройство выбирается до начала фоновых проверок.
**Отключить USB** освобождает порт, но не останавливает работу самой ESP32.
Для прошивки сначала отключите USB в приложении. Не открывайте одновременно
два экземпляра программы для одного COM-порта.

Пароль вводится заново после перезапуска платы. Он не встроен в исходники,
не печатается в журнал и не сохраняется приложением на диск.
ESP32 держит пароль в RAM для переподключения; новые Wi-Fi credentials
не записываются во flash (`WiFi.persistent(false)`). Старые записи NVS от
предыдущих версий прошивки не стираются автоматически.
Поскольку пароль не сохраняется приложением, кнопку подключения нужно
нажать снова с заново введённым паролем после неудачной попытки.

Сохранённый ранее режим назначения IP найденного устройства самой ESP32
оставлен без изменения по запросу пользователя; при активном устройстве
он может создавать конфликт адресов и влиять на результаты диагностики.

## Если что-то не работает

- «Отказано в доступе» — порт занят другим монитором. Закройте его.
- Нет COM-порта — проверьте кабель и драйвер CH340/CP210x.
- Нет ответа новой прошивки — нажмите EN/RESET либо загрузите версию из
  этого проекта. Старый скетч без USB-протокола не поддерживается.
- Нет устройств — дождитесь повторного сканирования; точка доступа может
  изолировать Wi-Fi клиентов. Поддерживается IPv4-подсеть до 1024 хостов.
- После отключения кабеля подключитесь к порту заново и повторите мастер.
- USB не шифрует пароль: используйте собственный компьютер и доверенный кабель.

## Исходники и пересборка

- app.py — окно Tkinter, таблицы, состояния, журнал.
- protocol.py — проверка JSON-событий и порядок ответов плате.
- transport.py — фоновое чтение/запись serial, сброс через RTS.
- test_protocol.py — тесты порядка передачи пароля и переходов мастера.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
.venv\Scripts\python -m unittest test_protocol -v
.venv\Scripts\python -m PyInstaller --onefile --windowed --name ESP32-Network app.py
```

USB-протокол версии 1: плата публикует отдельные строки `@ESP32 {JSON}`
рядом с обычным журналом Serial. Ответы передаются строками UTF-8 с LF.
SSID и устройства передаются с индексом; клиент отправляет индекс только
в состоянии соответствующего выбора, пароль и имя — только по запросу платы.
Длина входной строки прошивки ограничена 256 байт, имени GUI — 128 байт.
