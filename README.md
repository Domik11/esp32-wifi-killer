# ESP32 Network Lab

Образовательный проект для изучения ESP32, Wi-Fi, ARP, IPv4, DNS PTR,
Preferences/NVS и обмена с Windows-приложением через USB Serial.
Исходный Arduino-скетч перенесён в модульный проект PlatformIO для VS Code.

## Возможности

- Windows-окно: COM-порт, выбор Wi-Fi, ввод пароля, выбор и именование устройства.
- Переподключение к выбранной сети, даже после потери связи.
- ARP-сканирование IPv4-подсети, получение IP/MAC и DNS PTR-имён.
- Сохранение выбранного IP, MAC и имени в NVS.
- Фоновый поиск преимущественно по MAC и обновление IP при изменении.
- Состояние Wi-Fi, RSSI и ICMP-проверка `yandex.ru`.

## Требования

ESP32 Dev Module (`esp32dev`), USB-кабель с передачей данных, VS Code
с расширением **PlatformIO IDE** или отдельный PlatformIO Core.
Для Windows-приложения требуется Windows x64; Python 3.11+ нужен только
для запуска исходников и пересборки exe. Для USB-UART может понадобиться
драйвер CH340/CP210x.

Зафиксированы Espressif32 6.12.0, Arduino Core 2.0.17 и ESP32Ping 1.7.
WiFi, WiFiUDP, Preferences, lwIP и FreeRTOS входят в framework.

## Сборка и прошивка

Откройте папку репозитория в VS Code, установите PlatformIO IDE и дождитесь
подготовки окружения. В терминале PlatformIO:

```sh
pio run
pio device list
pio run -t upload --upload-port COM5
```

`COM5` — пример: укажите порт своей платы. Перед прошивкой закройте все
программы, занимающие порт. Если зависло на `Connecting...`, зажмите BOOT
и отпустите при начале записи. Не стирайте всю flash, если нужно сохранить NVS.
Для другой модели платы проверьте `board` и таблицу разделов.

## Работа через Windows-окно

1. Запустите `ESP32-Network.exe`, выберите порт и нажмите **Подключить USB**.
   Приложение перезапустит ESP32 и получит список Wi-Fi сетей.
2. Выберите сеть, введите пароль и нажмите **Подключиться к Wi-Fi**.
   Для открытой сети пароль не нужен.
3. Дождитесь списка устройств, выберите строку, при желании задайте имя
   и нажмите **Выбрать и сохранить**.
4. Только после успешного выбора и сохранения запускаются фоновый поиск
   и диагностика. Устройство выбирается при каждом запуске платы.

**Начать заново** возвращает к выбору сети, **Отключить USB** освобождает
порт, но не останавливает уже работающую ESP32. Не открывайте один порт
одновременно в приложении, Arduino IDE и Serial Monitor VS Code.

### Сборка exe из исходников

```powershell
python -m venv windows_app/.venv
windows_app/.venv/Scripts/python -m pip install -r windows_app/requirements.txt
windows_app/.venv/Scripts/python windows_app/app.py
windows_app/.venv/Scripts/python -m PyInstaller --onefile --windowed --name ESP32-Network windows_app/app.py
```

Результат — `dist/ESP32-Network.exe`; Python на целевом ПК не требуется.
Альтернатива: `windows_app/build_windows.ps1` подготовит окружение, выполнит
тесты и создаст `windows_app/dist/ESP32-Network.exe`.
Детали: [Windows-приложение и протокол](windows_app/README.md).

### Обычный Serial Monitor

```sh
pio device monitor --port COM5 -b 115200
```

UTF-8, перевод строки LF. Отправляйте номер сети, пароль, номер устройства,
имя (пустая строка оставляет текущее). В журнале также видны строки
`@ESP32 {JSON}` для GUI. Выход из монитора — Ctrl+C.

## Поиск устройства и адресация

Трекер проверяет ARP-кеш **ESP32**, затем последний известный IP и подсеть
пачками по четыре адреса. MAC сравнивается без учёта регистра. PTR-имя
используется только без сохранённого MAC; `Unknown` не является идентификатором.
Произвольное пользовательское имя может не совпадать с PTR-именем.

При обнаружении IP обновляется в пространстве `lan-device`, ключи:
`ip`, `mac`, `name`. Подпись пользователя сохраняется. Если адрес не изменился,
повторной записи flash нет. Неудачный поиск повторяется через 5 секунд
после прохода, успешный — через 30. Сканирование работает задачей FreeRTOS.

Начальный адрес ESP32 получается по DHCP. В `include/network_config.h`
приведены только примеры из документационного диапазона, а не настройки автора.
`initializeIP()` в основном сценарии не вызывается. Для независимого
статического IP задайте собственные параметры и вызовите её до подключения.
Проверка формата IP не доказывает, что адрес свободен.

## Конфиденциальность

- Нет встроенного SSID, Wi-Fi пароля, облачных ключей или токенов.
- Пароль передаётся по USB только по запросу ESP32, не пишется в журнал или на диск.
- ESP32 хранит пароль в RAM для reconnect; `WiFi.persistent(false)` запрещает
  запись новых учётных данных во flash. После перезагрузки пароль вводится снова.
- Старые записи NVS от прежних прошивок автоматически не стираются.
- IP/MAC/имя устройства хранятся локально на плате; содержимое NVS не включено в репозиторий.
- USB-протокол не шифруется. Журнал в окне содержит данные вашей сети —
  проверяйте его и скриншоты перед публикацией.
- Прошивка обращается к DNS и отправляет ICMP-запросы к `yandex.ru`;
  облачной телеметрии приложения нет.
- `.gitignore` исключает журналы, сборки, локальные IDE-настройки и файлы секретов.

## Ограничения

- Только IPv4: до 1024 адресов хостов в подсети и до 64 устройств в списке.
- ARP-кеш может быть устаревшим; совпадение не доказывает активность устройства.
- Изоляция клиентов точки доступа, сон и задержки ARP мешают обнаружению.
- PTR-имя не гарантировано; `Unknown` допустим. Смена MAC требует нового выбора.
- ICMP-ответ не является проверкой HTTP/TLS или всего Интернета.
- Неудачный ping запускает reconnect не чаще раза в 15 секунд.
- Автоматическое присвоение IP устройства ESP32 может нарушить связь и
  дальнейшее сканирование; используйте изолированный учебный стенд.

## Проверки

```sh
python -m unittest discover -s windows_app -v
pio run
```

Тесты проверяют порядок передачи пароля, очистку старых учётных данных,
открытые сети, неверные состояния и ограничения ввода.
GitHub Actions собирает прошивку и Windows-приложение.

Локально проверены сборка, загрузка на ESP32, получение Wi-Fi сетей,
подключение через окно и список IP/MAC/PTR. Работа интерфейса подтверждена
пользователем. Это не заменяет проверку на вашей плате и сети.
Перед публикацией выполнены Gitleaks и дополнительная проверка известных
локальных данных: [отчёт](docs/PRIVACY_AUDIT.md).
